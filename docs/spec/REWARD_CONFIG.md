# REWARD CONFIG — RL の報酬設定と段位分布

状態：D-019・D-020・D-021 に基づく初版（仕様のみ。実装は RL 環境を作るときに行う）。

- **ルールの順位点（`rules` の `points.uma` など）と RL の報酬の順位点は別物**（D-019）。ルールの順位点はゲームの精算に使い、報酬はここで定める設定ファイルに持つ
- 報酬は**対局の終わり**に1回だけ決まる値（局ごとの報酬の作り方は `docs/02_RL_DESIGN.md` ③）

## 1. 報酬の形（D-020）
```
報酬 ＝ 順位点[順位] ＋ 持ち点の係数 ×（終局時の持ち点 − 基準点）
```
- 順位はゲームの精算と同じ決め方（`rules.table.tie_break`。天鳳三麻相当は起家に近い方が上位）
- 「終局時の持ち点」は精算前の持ち点（供託の精算 `rules.table.leftover_kyotaku` の後、ウマ・オカの前）
- 祝儀は入れない（D-013）

| 種類 | 順位点 | 係数 | 基準点 |
|---|---|---|---|
| 天鳳 | 段位ごとの順位ポイント | 0（順位だけ） | — |
| 雀魂 雀聖以下 | 段位ごとの順位点 | 1/1000 | 初期持ち点（`rules.points.starting`） |
| 雀魂 魂天 | 魂天専用の順位点 | 0 | — |

雀魂の段位点 ＝ 順位点 ＋（終局時の持ち点 − 初期持ち点）÷ 1000（出典：game8 の段位戦の解説。下の G8）。

## 2. 設定の形式（TOML）
```toml
[preset.tenhou-sanma-7dan-tonnan]
name = "天鳳三麻 七段（鳳凰卓・東南戦）"
rank_points = [135, 0, -135]   # 1位から順。人数分
score_coef = 0.0               # 持ち点 1 点あたり
score_base = 0                 # 基準点（score_coef = 0 なら使わない）
unit = "天鳳の段位pt"           # 表示用
source = "T-DAN（天鳳マニュアル 段位/昇段表 3人打ち、2026-11-25 取得）"
status = "confirmed"           # confirmed / guessed（推測を含む。オーナーの確認待ち）
scale = 135                    # 正規化の幅（§4）。省略時は (rank_points[0] − rank_points[-1]) / 2
```
- キーの意味：上の式のとおり。`score_coef` は持ち点1点あたりなので、雀魂の「÷1000」は `0.001`
- `status = "guessed"` のプリセットは、オーナーが確認するまで学習に使わない（読み込み時に警告し、`--allow-guessed` でだけ使える、を実装で行う）
- 実際のプリセットのファイルは RL 環境の実装と一緒に置く（予定：`rl/rewards/presets.toml`）。値は下の §3 を正とする

## 4. 報酬の正規化
プリセットによって報酬の大きさが桁違いになる（魂天は ±0.5、雀聖・天鳳は数百）。席ごとに違うプリセットで同じネットワーク（特に価値関数）を学習するので、**プリセットごとに決まった幅で割って、おおむね ±1 にそろえる**。

```
正規化した報酬 ＝ 報酬 ÷ scale
scale ＝ (rank_points[0] − rank_points[人数−1]) ÷ 2   （設定で上書き可）
```

| プリセット（東南） | scale | 1位 | 2位 | 3位 | 持ち点 +10000 の寄与 |
|---|---|---|---|---|---|
| tenhou-sanma-7dan | 135 | +1.00 | 0 | −1.00 | 0 |
| tenhou-sanma-10dan | 157.5 | +0.86 | 0 | −1.14 | 0 |
| mjsoul-sanma-jansei1-gyoku | 215 | +0.81 | 0 | −1.19 | +0.047 |
| mjsoul-sanma-jansei3-gyoku | 240 | +0.73 | 0 | −1.27 | +0.042 |
| mjsoul-sanma-konten | 0.5 | +1.00 | 0 | −1.00 | 0 |

- 割る数は**プリセットごとの定数**（学習の途中で変えない）。1つのプリセットの中では正の定数倍なので、そのプリセットの最適な打ち方は変わらない
- 同じ卓の中で席ごとにプリセットが違うと、各席の報酬の和は 0 にならない（ゼロサムでない）。価値関数は席ごとの報酬を予測する
- 学習の統計（`02_RL_DESIGN.md` の記録する統計）は正規化の前と後の両方を残す
- 別案：学習中の報酬の標準偏差で割る（PopArt など）。値が学習の進み方で変わり、再現と比較がしにくいので、まずは固定の幅にする

## 5. 抽選（D-021）
対象は**雀魂が雀聖以上、天鳳が七段以上**。

1. 対局ごと・席ごとに、プリセットを**段位の実際の分布（§6）に比例した確率**で選ぶ。席どうしは独立
2. 乱数は対局のシードから決める（`(game_seed, seat)` から導いた乱数。牌山の乱数とは別の系列）。同じシードなら同じプリセットになる（デュプリケート評価で、席を入れ替えてもプリセットは席に付いて動く、を基本とする）
3. 雀魂の魂天が全席に当たったら、全席を `-konten-all` にする
4. 選んだプリセットは**牌譜には書かず**、RL 側の対局の記録（自己対戦の出力の、対局ごとのメタデータ：`game_id` と席ごとのプリセット id）に残す。牌譜はゲームの事実だけの契約で、報酬は RL の設定なので分ける（D-019）
5. 抽選するかどうか・どの分布を使うかは RL の実行設定で決める（例：`reward.sampling = "tenhou-sanma-7dan+"`、`reward.fixed = "tenhou-sanma-7dan-tonnan"`）

### 報酬設定をモデルの入力に渡す形（D-021）
抽選する場合は、**各席のモデルの入力に、その席の報酬設定**を入れる。プリセットの id（one-hot）ではなく**数値**で渡す（プリセットを足してもネットワークの形が変わらず、近いプリセットどうしで学習が共有されるように）。

| 特徴 | 値 | 例（7段・東南） |
|---|---|---|
| 順位点（正規化） | `rank_points[i] / scale`（人数分。4人分の枠を取り、三麻は4つ目を 0） | [1.0, 0, −1.0, 0] |
| 持ち点の係数（正規化） | `score_coef × 10000 / scale`（持ち点 1万点あたりの寄与） | 0 |
| 基準点との差 | `(今の持ち点 − score_base) / 10000`（係数 0 なら 0） | 0 |

- 入力は「自分の席の設定」だけ（他家の報酬設定は、実際の対局では分からないので入れない）
- 抽選しない学習でも、同じ特徴を定数として入れておく（`02_RL_DESIGN.md`「最初から③の形にしておく」と同じ考え）
