# DECISION POINTS — 判断ポイントの仕様

状態：D-022 に基づく初版。エンジン（`mj-core`）の API の基本単位であり、注釈（`*.annot.jsonl`、LOG_FORMAT §6）と RL の行動選択の単位でもある。

- 実装：`crates/mj-core/src/kyoku.rs`（`Kyoku::decisions` が判断ポイント、`Kyoku::step` で行動を受け取る）、行動の表記と並び順は `crates/mj-core/src/action.rs`
- 検証：サンプルの牌譜をエンジンで再生し、注釈 4 件が判断ポイントで選択肢も一致すること（`crates/mj-log/tests/samples.rs`）、無作為な自己対戦で判断ポイントの選択肢が常に2つ以上・§5 の並びであること（`crates/mj-core/tests/selfplay.rs`）

## 1. 定義
- **判断ポイント**：エンジンがある席に**選択肢（見送りを含む）を2つ以上**提示した瞬間
- 注釈は判断ポイントごとに1つ。RL のエージェントが行動を選ぶ瞬間と同じ
- 選択肢が1つしかない場面（例：立直後にツモった牌を切るしかない）は判断ポイントにしない。エンジンがその1つを自動で選んで進める（牌譜にはふつうにイベントが出る）

## 2. 注釈のキー
- キーは `(game_id, kyoku_idx, event_idx, seat)`
- `event_idx` は**判断ポイントの直前に起きたイベント**（その時点で牌譜の最後にあるイベント）
- 例：席1が4pをツモって打牌を選ぶ → `event_idx` はその `tsumo`。席0が席2の打牌にポンするか選ぶ → その `dahai`

## 3. 同じ (event_idx, seat) に判断ポイントが2つ生じないことの保証
エンジンは次の3つの規則で作る。3つが成り立てば、キーは必ず一意になる。

| 規則 | 内容 |
|---|---|
| **R1 1つの場では1席1判断** | エンジンは判断を「場」の単位で出す（ある時点で判断を待っている席の集合）。1つの場では、各席の選択肢を**1つのリスト**にまとめる。例：打牌に対して「ロン・ポン・見送り」ができる席には、3つを並べた1つの判断を出す（ロンの判断とポンの判断に分けない） |
| **R2 続けて選ぶものは1つの複合行動にする** | 間にイベントが起きない2つの選択は、1つの行動にまとめる。**立直は「立直してこの牌を切る」**（`reach:8p`）。**ノーテン宣言は「見送ってノーテンと宣言する」**（`pass:noten`） |
| **R3 場が解決したら必ずイベントが出る** | 場の全員の選択がそろって解決すると、次の場を出す前に**必ず1つ以上のイベント**が牌譜に出る（下の表）。したがって、同じ `event_idx` を直前のイベントとする場は1つしかない |

R3 の確認（場の解決 → 必ず出るイベント）：

| 場 | 解決の結果 | 出るイベント |
|---|---|---|
| ツモ後の判断 | 打牌・立直・暗槓・加槓・北抜き・ツモ和了・九種九牌 | `dahai`／`reach`→`dahai`／`ankan`／`kakan`／`kita`／`hora`／`ryukyoku` |
| 鳴いた後の判断 | 打牌（・北抜き） | `dahai`（／`kita`） |
| 打牌への応答 | ロンがある | `hora` |
| | ロンがなく鳴きがある | （立直の宣言牌なら `reach_accepted`）→（後めくりの `dora`）→ `pon`／`chi`／`daiminkan` |
| | 全員見送り | （`reach_accepted`）→（後めくりの `dora`）→ 次の `tsumo`、または `ryukyoku` |
| 加槓・暗槓・北抜きへの応答 | ロンがある | `hora` |
| | 全員見送り | （`dora`）→ 嶺上の `tsumo` |
| 河底の打牌への応答（ノーテン宣言あり） | 全員見送り | `ryukyoku` |

## 4. 判断ポイントの一覧

「直前のイベント」が注釈の `event_idx` になる。選択肢の表記は §5。

| # | いつ | 誰に | 選択肢の例 | 直前のイベント | 備考 |
|---|---|---|---|---|---|
| 1 | 山から牌をツモったとき | ツモった人 | 打牌（`dahai:3p`、ツモ切り `dahai:9s:tsumogiri`）、立直して打牌（`reach:8p`）、暗槓（`ankan:E`）、加槓（`kakan:C`）、北抜き（`kita`）、ツモ和了（`tsumo`）、九種九牌（`kyushu`） | `tsumo` | 打牌の選択肢は手牌の種類ごと（赤は別）。ツモった牌と同じ牌が手にあれば、手出しとツモ切りは別の選択肢 |
| 2 | 嶺上牌をツモったとき（槓・北抜きの補充） | ツモった人 | 1 と同じ（ツモ和了は嶺上開花） | `tsumo`（`rinshan: true`） | 九種九牌は出ない |
| 3 | ポン（チー）をした直後 | 鳴いた人 | 打牌（喰い替えになる牌は除く）、北抜き（`kita.after_pon = true` のときだけ） | `pon`／`chi` | ツモ和了・立直・槓はない |
| 4 | 他家が打牌したとき | 打牌者以外で、ロン・ポン・チー・大明槓のどれかができる人 | `ron`、`pon:5p,5pr`、`chi:3s,4s`、`daiminkan`、`pass` | `dahai` | ロンができるのに見送るのは「見逃し」（同巡内の振聴になる。立直中なら以後ずっと振聴） |
| 5 | 立直の宣言牌が打たれたとき | 4 と同じ | 4 と同じ | `dahai`（その前に `reach`） | 宣言牌でのロンなら立直は不成立（`riichi.no_deposit_on_deal_in`）。見送り・鳴きなら `reach_accepted` が出てから次へ |
| 6 | 北が打牌されたとき（切った北へのロン） | 北待ちで役がある人（`kita.ron_on_discard = true`）、ポンできる人 | `ron`、`pon:N,N`、`pass` | `dahai` | 4 の一種 |
| 7 | 他家が北を抜いたとき（北抜きへのロン） | 北待ちで役がある人（`kita.ron_on_kita = true`） | `ron`、`pass` | `kita` | 鳴きはない。槍槓は付かない（`kita.ron_counts_as_chankan = false`）。見送りは見逃し（振聴）。見送りなら抜いた人が嶺上牌をツモる（2 へ） |
| 8 | 他家が加槓したとき（槍槓） | その牌で和了できる人 | `ron`、`pass` | `kakan`（カンドラ即乗りの設定なら、その後の `dora`） | 槍槓（1翻）が付く |
| 9 | 他家が暗槓したとき（国士無双の槍槓） | 国士無双でその牌を待つ人（`yakuman.kokushi_ron_on_ankan = true` のときだけ） | `ron`、`pass` | `ankan`（即乗りならその後の `dora`） | 天鳳三麻相当では出ない |
| 10 | 第1ツモ（鳴き・北抜きの前）で么九牌が9種以上 | ツモった人 | 1 の選択肢に `kyushu` が加わる | `tsumo` | 1 の一種。独立した判断ポイントにはしない（R1） |
| 11 | 1つの打牌に2人以上がロンできるとき（ダブロン） | ロンできるそれぞれの人 | 各自 `ron`／`pass`（鳴きもできれば加わる） | `dahai` | 同じ `event_idx` で**席が違う**判断ポイントが2つ。互いの選択を知らずに選ぶ。`calls.max_ron` を超えたら頭ハネ（放銃者の下家から順に優先） |
| 12 | 大明槓・加槓の後の打牌（カンドラ後めくり） | 4 と同じ | 4 と同じ | `dahai`（天鳳三麻・雀魂三麻。`kan_dora_timing = "ankan_immediate_after_pass"`）／`dora`（`ankan_immediate`・`all_delayed`） | 天鳳三麻・雀魂三麻：打牌 → 応答 → 打牌が通れば `dora`（ロンされたら `dora` は出ない。D-027、オーナー回答 C）。majiang-core と同じ値（`ankan_immediate`）では 打牌 → `dora` → 応答 の順で、直前のイベントは `dora` |
| 13 | 立直中にツモったとき | ツモった人 | ツモ和了（`tsumo`）、ツモ切り（`dahai:6p:tsumogiri`）、待ちの変わらない暗槓、ツモった北の北抜き（`kita.after_riichi = "drawn_only"`） | `tsumo` | ツモ切りしかなければ判断ポイントにしない |
| 14 | 最後のツモ（海底） | ツモった人 | ツモ和了、打牌 | `tsumo` | 槓・北抜きはできない（王牌は常に `wall.dead_wall` 枚で、補充する山が残っていないため）。`riichi.requires_draw = true` なら立直もできない |
| 15 | 最後の打牌（河底）への応答 | ロンできる人（`calls.haitei_call = true` なら鳴ける人も） | `ron`、`pass` | `dahai` | ノーテン宣言ありなら 16 と合わせる |
| 16 | 荒牌流局の直前（ノーテン宣言、`draws.noten_declaration = true` のときだけ） | 聴牌している人 | 打牌者：`declare:tenpai`／`declare:noten`。それ以外：`pass`（聴牌のまま）／`pass:noten`（ノーテンと宣言）／`ron` | 河底の `dahai` | 15 と同じ場（R1）。宣言は見送りと1つの行動にする（R2）。天鳳三麻相当では出ない |

### 判断ポイントにならない場面（エンジンが自動で進める）
- 選択肢が1つしかない（立直後に切るしかないツモ、見送りしかできない打牌、鳴いた後に切れる牌が1種類だけ）
- 流局・和了の精算、途中流局（全員立直・四風連打・四槓散了・全員のロン）の判定、和了止め・聴牌止め（`table.oorasu_stop = "auto"`）
- 北抜きの強制（`kita.mandatory = true`）：北を持っていれば北抜きしか選べない場面は判断ポイントにしない

## 5. 選択肢の表記と並び順（決定論）

| 表記 | 意味 |
|---|---|
| `dahai:<牌>` | 手の中の牌を切る（手出し） |
| `dahai:<牌>:tsumogiri` | ツモった牌を切る |
| `reach:<牌>`／`reach:<牌>:tsumogiri` | 立直して切る（複合行動） |
| `ankan:<牌の種類>` | 暗槓（赤を含めて4枚すべて） |
| `kakan:<牌>` | 加槓（加える牌） |
| `kita` | 北抜き |
| `tsumo` | ツモ和了（嶺上開花を含む） |
| `kyushu` | 九種九牌の流局 |
| `ron` | ロン和了（槍槓・北抜きへのロンを含む） |
| `pon:<牌>,<牌>`／`chi:<牌>,<牌>` | 手から出す2枚（赤の有無で別の選択肢） |
| `daiminkan` | 大明槓 |
| `pass` | 見送り |
| `pass:noten`／`declare:tenpai`／`declare:noten` | ノーテン宣言（16） |

牌は MJAI の表記（LOG_FORMAT §3）。**並び順**は次の順で固定する（同じ局面・同じルールなら常に同じ並び）：
1. 行動の種類：`tsumo` → `ron` → `kyushu` → `ankan` → `kakan` → `kita` → `daiminkan` → `pon` → `chi` → `reach` → `dahai` → `declare` → `pass`
2. 同じ種類の中は牌の順（種類の昇順、赤が先。`pon`・`chi` は2枚の並びで比べる）
3. 同じ牌なら手出しが先、ツモ切りが後。`declare:tenpai` が `declare:noten` より先、`pass` が `pass:noten` より先

## 6. 応答の解決（同時の判断の決め方）
1. 応答の場では、全員の選択がそろってから解決する（互いの選択は見えない）
2. ロンが最優先。`calls.max_ron` 人まで、放銃者の下家から順（頭ハネ）。放銃者以外の全員がロンし `draws.all_ron = true` なら流局
3. ロンがなければ大明槓・ポン、その次にチー
4. 見送った席のうち、ロンできた席は見逃しの振聴になる

## 7. 確認の結果（D-027、2026-11-28）
1〜4 はオーナーが承認した（3 は回答 C で置き換え：天鳳三麻・雀魂三麻では、後めくりのカンドラは打牌が通った後にめくるので、直前のイベントは `dahai`）。2 は回答 B（海底の槓・北抜きは不可）で確認された。

1. **手出しとツモ切りを別の選択肢にした**：同じ牌を手出しかツモ切りかで切り分けられる（他家から見える情報が違うため）。行動の数は少し増える
2. **海底では槓・北抜きができない**とした：オーナー回答の「王牌は常に14枚」から導いた（補充する山がない）。→ 回答 B で確認（天鳳・雀魂とも不可）
3. ~~カンドラ後めくりの打牌では、直前のイベントが `dora` になる~~ → 回答 C で、天鳳三麻・雀魂三麻では打牌が通った後にめくるので直前のイベントは `dahai`（`ankan_immediate` などの値を使う四麻のテスト用ルールでは `dora`）
4. **選択肢が1つの場面は RL のエージェントに見せない**（例：立直後のツモ切り）。学習の1歩にも数えない
5. ノーテン宣言（16）は複合行動にした。天鳳三麻相当では出ないので、当面は実装とテストだけ持つ
