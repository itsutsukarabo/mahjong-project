# REPLAY UI — 2D の牌譜再生画面の仕様

状態：**Claude Code の案（2026-11-28）**。オーナーが他の麻雀アプリの三麻の牌譜再生で見せた「挙動と情報の見せ方」を、
見た目（牌の絵柄・背景の質感・書体・配色）は真似せずに取り入れた。参考の動画は見ていないので、あいまいな点は
下の「決めたこと」（§11）で決めた。オーナーの確認待ち。

- 実装：`web/apps/replay`（画面・操作）、`web/packages/render-2d`（描画）、`web/packages/table-model`（再生の位置・帯の区画・注釈の振り分け・アニメーションの手がかり）
- 卓の状態は Rust（`mj_log::view`）が作り、WASM（`crates/mj-wasm`）から受け取る。画面側に和了判定・点数計算・合法手の判定は書かない（CLAUDE.md 原則1）
- 描画は DOM（D-059）

## 1. 動かし方
```bash
pnpm install && pnpm build:wasm && pnpm --filter @mj/replay dev       # http://localhost:5173
# 例：?log=fixtures/rl-u157.mjlog.jsonl&annot=fixtures/rl-u157.annot.jsonl&kyoku=0&event=1
```
URL の引数：`log`・`annot`（URL）、`kyoku`（局の番号 0〜）、`event`（event_idx。負なら後ろから）、`seat`（視点の席）、
`dev`（0/1：全員の手牌）、`ai`（0/1：AI の判断）、`anim`（0/1：アニメーション）、`layout`（auto/landscape/portrait）、`speed`（ms/手）

## 2. 構成（描くまでの流れ）
```
牌譜 ──WASM──▶ TableView[]（各イベントの直後の卓）
                 │ table-model：ReplayModel（位置）・bandSlots（帯の区画）・layoutAnnotation（注釈の振り分け）
                 │              cuesBetween（前の卓と次の卓の差 → どの牌がどこからどこへ動いたか）
                 ▼
             render-2d：computeMetrics（画面の寸法）→ render（DOM を作り直す）→ playCues（アニメーション）
```
- 毎手、DOM を作り直す。アニメーションは「作り直す前の牌の位置（`data-key` ごとの画面上の矩形）」と「作り直した後の同じキーの牌」の差で動かす（FLIP）。どの牌が動いたかは `cuesBetween` が前後の `TableView` の差（イベントの種類、手牌・河・副露の並び）だけから決める
- 牌の要素のキー（`placeKey`）：`h:<席>:<i>`（手牌）・`d:<席>`（ツモ牌）・`r:<席>:<i>`（河）・`m:<席>:<i>`（副露）・`k:<席>:<i>`（抜いた北）・`dora:<i>`

## 3. 配置
画面の大きさで2つの配置を切り替える（`chooseLayout`：幅 < 700 か、幅 < 高さ × 0.8 なら縦画面）。メニューで固定もできる。
牌の大きさは、河の牌の幅を大きい方から1px ずつ試して全体が入る最大のものにする（すべて整数の px。拡大縮小の transform は使わない＝高 DPI でにじまない。牌は SVG）。

### 3.1 横画面（PC）
- 下：視点の席の手牌（大きく）、その下に帯（§4）、その下に区画に結び付かない選択肢の一覧（§6）
- 中央：情報パネル（正方形）の上下左右に各席の河。河は各席の向きに回す（6 枚ずつ、4 段分の枠）
- 盤の左右（四麻は上も）：他家の手牌（その席の向きに回す。全情報版は表、公開情報版・開発者モードを切ると裏）。手牌 → ツモ牌 → 副露 → 抜いた北の順
- 十字の四隅：各席の名前の札（その席の手牌が始まる側の角）
- 画面の左上の隅：ドラ表示牌
- 幅 1200px 以上なら右に詳細の欄（この時点の全席の注釈を確率の高い順に全部）

### 3.2 縦画面（スマホ）
- 上：他家を1席1段で並べる（上家 ← ・対面 ↑・下家 → の順。回さない）。段は「札（向き・風・名前・段位の枠・立直）」と「手牌・ツモ牌・副露・抜いた北」
- 真ん中：河と中央パネルの十字（横画面と同じ。回す）。十字の左上の隅にドラ表示牌
- 下：視点の席の札と副露・抜いた北（右寄せ）の段 → 手牌 → 帯 → 一覧 → 操作のボタン
- 余った高さは帯に回す（72px まで）

### 3.3 三麻の空いた席
- **視点の席を下、下家を右、上家を左に置き、上（対面の位置）を空ける**（実物の三麻の卓と同じ向き。四麻と同じ回転・同じ部品で描ける）
- 横画面：上の腕は河を置かず、左の席の札が入るだけ（72px）に詰める。その分、牌を大きくする（1440×900 で河の牌 36px → §3.4）
- 縦画面：十字は四麻と同じ正方形のまま（上の腕は空く。高さに余裕があるため）

## 4. 手牌の下の帯
### 4.1 形
- 視点の席の手牌の真下の横長の帯。**区画 = 手牌の各牌（ツモ牌を含む）と同じ幅**。区画の境目に 1px の線
- 区画は「牌＋帯のマス」を1つの縦の列（`.slot`）にして作るので、牌と区画の左右は構造でそろう（テストでも確かめる：§9）
- ツモ牌の前の隙間（牌の幅の 0.4 倍）は、帯の地だけを続ける（区画ではない）
- 副露・抜いた北の下には帯を置かない
- 高さ：横画面は牌の高さの 0.62 倍（最低 40px）、縦画面は牌の高さの 1.3 倍（最低 48px）＋余った高さ（72px まで）。390×844 で 25×72px（Apple の推奨の 44pt 以上）

### 4.2 区画と牌の対応（ゲームモードで使う仕組み）
`@mj/table-model` の `bandSlots(seat)`：区画 i → `{ tile, drawn, handIndex, action }`。
- 区画 0..k−1 は手牌（整列済み）の順、ツモ牌があれば最後の区画
- `action` はその牌を切る行動の表記（DECISION_POINTS §5）：手牌は `dahai:<牌>`、ツモ牌は `dahai:<牌>:tsumogiri`
- `actionOfSlot(slots, i)`：押した区画 → 送る行動。`slotOfAction(slots, action)`：行動 → 区画
- **合法手の判定はしない**。ゲームモードでは、エンジンが返す合法手の一覧に `action` があるかで区画を押せるかを決める（原則1）。立直の打牌（`reach:<牌>`）は、立直のボタンを押してから区画を押す形を想定（未実装）
- DOM：`.slot[data-slot=i][data-action=…]`、その中の `.band-cell[data-slot=i]`

### 4.3 同じ牌が2枚以上あるとき
判断の選択肢は牌の種類ごと（DECISION_POINTS §4 の 1）なので、`dahai:5p` は**左から最初の区画**に結び付ける。同じ牌の2枚目以降の区画は空ける。ツモ牌と同じ牌が手にあれば、手出し（手牌の区画）とツモ切り（ツモ牌の区画）は別の選択肢として、それぞれの区画に出る。

## 5. 動き
### 5.1 牌の動き（`cuesBetween` → `playCues`）
| イベント | 動き |
|---|---|
| `tsumo` | ツモ牌が上から現れる |
| `dahai` | 手牌（またはツモ牌）の位置から河の位置へ。手牌の並べ直し（ツモ牌が手牌に入る）も動かす |
| `chi`・`pon`・`daiminkan` | 鳴かれた河の牌から副露の位置へ。手牌の並べ直し |
| `ankan`・`kakan` | 副露が現れる |
| `kita` | 手牌（ツモ牌）から抜いた北の位置へ |
| `dora` | ドラ表示牌が現れる |

- 1手進んだときだけ動かす（戻る・局の移動・巡目のシークは動かさない）
- 時間：手動で進めたとき 240ms、自動再生では min(240ms, 1手の間隔 × 0.6)。手牌の並べ直しはその 0.8 倍
- Web Animations API だけを使う（毎フレームの JS を書かない）。メニューの「アニメーション」で切れる（URL `anim=0`）。切るとアニメーションは1つも作らない（テストで確かめる）

### 5.2 大きな文字
ポン・チー・カン（大明槓・暗槓・加槓）・キタ・リーチ（`reach` の時点）・ロン・ツモを、その席の河の中心に一瞬出す（拡大して現れ、0.7 で止まり、消える。max(500ms, 動きの 3.5 倍)）。アニメーションを切ると出さない。

### 5.3 結果の窓
- 和了（`hora` の時点から局の終わりまで）：和了者・ツモ／ロン（放銃者）、点数の名前（§8 の制約あり）と点数、和了形（手牌＋和了牌＋副露）、役と翻数（役満は倍数）、ドラ・赤ドラ・裏ドラ・抜きドラの翻数（0 は薄く）、翻と符、ドラ表示牌・裏ドラ表示牌、各席の「前の点数・増減・後の点数」（増は緑、減は赤）。同時和了はすべての和了を並べ、増減は合計
- 流局：種類、各席の聴牌・ノーテンと公開された手牌（`ryukyoku.hands`、非公開は「手牌は非公開」）、点数の増減
- 対局の終わり（最後の時点）：順位・名前・点数・精算（`game_end.settlement`）、祝儀（0 以外があるときだけ）、飛び
- 閉じるボタン（Esc でも閉じる）。閉じたら同じ局の同じ結果では出さない
- 自動再生：窓が開いたら min(4s, max(1s, 間隔 × 8)) 止めてから自動で閉じて進む。対局の終わりの窓で止まる

## 6. AI の判断の表示（D-022 の注釈）
- 視点の席の判断ポイント（その時点のイベントをキーに持つ注釈）を表示する。他の席の判断は「席 N の判断 →」のボタン（押すとその席を視点にする）と、横画面の右の欄に出る
- **帯**：打牌の選択肢ごとに、その牌の真下の区画に確率の棒（区画の高さ = 確率 100%）と百分率。実際に選んだ行動の区画は黄色の枠と黄色の棒、一番確率の高い行動に ★
- **一覧**（帯の下の1行。横に送れる）：区画に結び付かない選択肢（ツモ和了・ロン・九種九牌・暗槓・加槓・北抜き・大明槓・ポン・チー・立直・見送り・宣言）を、牌の小さな絵と確率と一緒に。手牌が見えない（公開情報版）ときは打牌もここに出る
- **選んだ行動 ≠ 最大確率**：「★最大確率と違う行動を選んだ」を出す（選んだ行動の確率が最大より小さいとき。同じ確率は違いとしない）
- **価値**：数値（小数3桁）と小さなメーター（−1〜+1 を中央 0 で塗る。範囲外は端で止める）。価値の単位は学習の報酬の正規化による（RL_TRAINING）ので、メーターは目安
- **表示の ON・OFF**：メニューの「AI の判断」（URL `ai=0`）。切ると帯は空、一覧は「切」とだけ出る（配信用）

### 6.4 抽選の牌譜か、最大確率の牌譜か
次の順で判断して一覧の左端に「抽選」「最大確率」「選び方不明」を出す（根拠は札のツールチップとメニュー）：
0. 注釈の `selection` 欄（`"sample"`／`"greedy"`）。学習のセッションが LOG_FORMAT §6 に足した任意の欄（a5fb2f1）。全部が同じ値ならそれ、混在なら「不明（混在）」
1. 欄がない（古い注釈ファイル）とき、注釈のファイル名に、区切り（`.` `_` `-` `@`）で囲まれた `greedy`・`argmax` があれば最大確率、`sampled`・`sampling`・`stochastic` があれば抽選
2. 注釈の `model` に同じ語があれば同じ
3. 中身から推定：選んだ行動の確率が最大より小さい判断が1つでもあれば抽選。1つもなく、確率が一様でない判断が 10 個以上なら「最大確率（推定）」。それ以外は不明（例：RuleBot の注釈は確率が一様なので不明）

→ 学習のセッションへの提案は §8。

## 7. 牌の絵（仮）
- `web/packages/render-2d/src/tile-art.ts` の `tileArt(牌の表記)` だけが「牌の種類 → 絵」の対応（幅 60 × 高さ 80 の SVG の中身）。差し替えるときはここを変える（`<image href>` を返してもよい）
- 絵は文書に1回だけ `<symbol>` で入れ、各牌は `<use>` で参照する（DOM の数を減らす）
- 意匠（独自）：象牙色の地＋下に厚み。数牌は大きな算用数字＋下に小さな「萬・筒・索」＋左上に種類の印（萬＝菱形、筒＝輪、索＝縦の棒。色だけに頼らない）。萬は紫がかった赤、筒は青、索は緑。字牌は漢字1字、白は青灰の枠だけ
- 赤5：数字と印を赤、地をうすい赤、右上に赤い丸
- 裏：青緑の地＋内側の線＋菱形
- 横向き：同じ絵を左に 90° 倒す（立直の宣言牌・鳴いた牌・加槓）

## 8. 牌譜・WASM に足りない情報（mj-core・mj-log の変更が要るもの。今回は直していない）
| 足りないもの | 今の扱い | 提案 |
|---|---|---|
| 点数の名前（満貫など）の区分 | 翻数だけで決まるもの（5翻以上・役満・数え役満）だけ名前を出す。3・4翻の満貫（4翻30符・3翻60符は `points.kiriage_mangan` で変わる）は名前を出さず「n翻m符・点数」だけ | `hora` か `TableView.result` に、エンジンが決めた区分（`limit`: `none`/`mangan`/`haneman`/…）を足す（mj-core の点数計算が `b >= 2000` などで判定済み） |
| 注釈の「選び方」（抽選・最大確率） | §6.4。`selection` 欄があればそれを使う（学習のセッションが mj-log と LOG_FORMAT §6 に足した。a5fb2f1） | 欄が入ったら解決。古いファイル（今の fixtures の rl-u157 など）は中身からの推定のまま |
| 段位など | 枠だけ（「段位 —」） | `game_start.players` に任意の `rank` など |

## 11. 決めたこと（参考にした挙動の範囲で、Claude Code が決めた）
- 三麻の空いた席：§3.3
- 縦画面の配置：§3.2（他家は上に1席1段、回さない）
- 帯の寸法：§4.1。同じ牌の区画：§4.3（左から最初）

- 配色：濃い青灰の地、黄色＝手番・選んだ行動、緑＝点数の増加・価値の正、赤＝減少・価値の負（他のゲームの緑の卓・木目などは使わない）
