# OBSERVATION — RL の観測

状態：D-042・D-043 に基づく初版の実装（2026-11-29）。実装は `crates/mj-features/src/obs.rs`（`Observer::observe`）。

## 1. 方針
- **観測を作る実装はここ1つだけ**（D-043）。RL の学習（mj-py）・対戦サーバー・FE（WASM）のすべてがこれを呼び、ほかの言語で作り直さない
- **方策の入力**（`policy`・`events`・`mask`）は、局の全情報のイベント列から作った**席視点のイベント列**（`obs::seat_view`。LOG_FORMAT §5 の席視点版と同じ範囲）だけから作る。他家のツモ・他家の配牌・牌山・めくっていない表示牌・裏ドラは、ここで落とす
- **価値関数だけの入力**（`critic`）は全情報のイベント列から作る。学習時だけ使い、方策には渡さない
- 判断ポイントごとに作る（D-022。選択肢が1つの場面では作らない。D-027）
- 同じ入力からは常に同じ観測になる（乱数・時刻・ハッシュの順序に依らない）
- 1局戦でも半荘の形（点数・局・本場・ルール設定・報酬設定）で入れる（02_RL_DESIGN「最初から③の形にしておく」）。席は4つの枠（三麻は4つ目を 0）

## 2. 方策の入力 `policy`（固定長 439、`Observer::layout()`。ルールの項目を足すと `rules` の区画が伸びる）
| 区画 | 次元 | 中身 |
|---|---|---|
| `hand` | 74 | 自分の手の中の牌（34 種 × 枚数 / 4）、赤を持つか（5m・5p・5s の 3）、ツモった牌（牌の番号 37 の one-hot） |
| `self` | 4 | 自分のシャンテン数（(n + 1) / 8）、受け入れ枚数（/ 60。13 枚形のとき）、立直中か、捨て牌フリテンか |
| `discard_candidates` | 111 | 打牌の候補ごと（牌の番号 37）に：候補か（mask）、切った後のシャンテン数、切った後の受け入れ枚数（D-042） |
| `table` | 17 | 場風（4）、何局目（4）、親の相対の席（4）、本場 / 10、供託 / 10、ツモ山の残り / 70、延長戦中か、規定の最後の局か |
| `seats` | 32 | 相対の席（自分・下家・対面・上家）ごとに7つ：持ち点 / 10000、自分との点差 / 10000、順位 / 4、立直、北抜き / 4、副露の数 / 4、河の枚数 / 24。最後に自分の順位の one-hot（4） |
| `tiles` | 68 | ドラになる牌の種類ごとの枚数（34。表示牌から変換し、抜いた北のドラ `kita.dora_per_kita` を北に足す。D-042）、見えている枚数（34） |
| `rules` | 127 | カタログで「打ち方に効く」印（`Item::play`）の付いた 88 項目を、カタログの順に数値にしたもの（真偽値 0/1、点の項目 / 10000、ほかの整数 / 10、順位点は4人分、列挙は one-hot、集合は multi-hot） |
| `reward` | 6 | 報酬設定（REWARD_CONFIG §5）：順位点（正規化、4人分）、持ち点の係数 × 10000、基準点との差 / 10000 |

- シャンテン数・受け入れは、自分の手牌と見えている牌（河・副露・北抜き・表示牌）だけから数える（D-042）
- 持ち点は1万点で割る。三麻と四麻で大きさをそろえない（人数はルール設定で伝わる。D-042）
- 順位は、同点なら起家に近い席が上（`table.tie_break = seat_order` と同じ数え方）

## 3. イベント列 `events`（トランスフォーマーに渡す前提、D-042）
局の始めからのトークンの列。トークンは6つの整数：

| 欄 | 中身 |
|---|---|
| 0 種類 | 1 ドラ表示 / 2 ツモ / 3 打牌 / 4 立直の宣言 / 5 立直の成立 / 6 チー / 7 ポン / 8 大明槓 / 9 暗槓 / 10 加槓 / 11 北抜き |
| 1 席 | 自分から見た相対の席（0 自分・1 下家・2 対面・3 上家） |
| 2 牌 | 牌の番号（0〜36、ACTION_SPACE §2）。37 ＝ 見えない（他家のツモ、公開しない暗槓）、38 ＝ 牌なし（立直など） |
| 3 付加1 | 打牌：ツモ切りか。ツモ：嶺上か |
| 4 付加2 | 打牌：立直の宣言牌か。鳴き：鳴いた相手の相対の席 |
| 5 位置 | 局の中の順番（0 から）。イベントの順番の情報（D-042） |

- 局の最初のドラ表示牌も先頭のトークンとして入る（表示牌そのものはイベント列に残す。D-042）
- 前の局の流れはイベント列に入れない（対局の状態は `table`・`seats` に入る）

### 列の長さ（ボット同士の対局で実測、D-042）
`cargo run --release -p mj-features --example obs_bench -- --rules <rules> --games 2000 --seed 1`（mj-bots の RuleBot、局の終わりの時点のトークン数）：

| ルール | 局数 | 1局：平均 | p99 | p99.9 | 最大 | 1半荘：平均 | p99 | 最大 |
|---|---|---|---|---|---|---|---|---|
| 天鳳三麻（東南戦） | 17,779 | 77.1 | 117 | 119 | 120 | 685.4 | 1,240 | 1,473 |
| 四麻（test-yonma、東南戦） | 21,870 | 108.0 | 148 | 150 | 152 | 1,181.5 | 1,946 | 2,512 |

- **上限は1局 192 件**（D-045、`obs::MAX_EVENTS`。mj-py の `max_events` の既定）。列は局ごとなので半荘の長さは使わない
- 上限を超えた行は、先頭から 192 件を入れ、`events_overflow` に印を付けて数え（`VecEnv.overflow_total`）、警告を出す。古いイベントを黙って捨てることはしない。テスト（`observation.rs`・mj-py の `env.rs`）では超えたら失敗にする。学習中に超えた回数は統計に残す（D-045）
- ボットは降りや鳴きが少ないので、強い打ち手では長さが変わりうる［推測］。学習が進んだら測り直す

## 4. 合法手マスク `mask`
325 個（ACTION_SPACE）。選択肢の番号が true（`mj_features::legal_mask`）。方策の出力は 325 個の1段で、マスクで使えない行動を消す（D-039）。

## 5. 価値関数だけの入力 `critic`（173）
他家の手牌（相対の席 1〜3、34 種 × 枚数 / 4 ＝ 102）、ツモ山の残り（めくっていない表示牌を含む、34）、裏ドラ表示牌（めくった枚数分、34）、他家のシャンテン数（3）。

## 6. 検査（`crates/mj-features/tests/observation.rs`）
1. **漏れの検査**：自己対戦（天鳳三麻・雀魂三麻・四麻、ボットと一様な乱数）のすべての判断ポイントで、全情報のイベント列の隠れた欄（他家の配牌・他家のツモ・牌山・めくっていない表示牌・裏ドラ）を乱数の牌に書き換えても、`policy`・`events`・`mask` が完全に一致する。`critic` は変わる（区画が分かれていることの確認）
2. **決定論**：同じ局面から2回作っても、別の `Observer` で作っても同じ
3. 区画の次元が `Layout` と一致し、値がすべて有限

## 7. 速さ
`Observer::observe` 1つ：天鳳三麻 267 µs、四麻 255 µs（1スレッド、Windows ネイティブ、`obs_bench` の 2000 半荘）。大半は打牌の候補ごとのシャンテン数・受け入れの計算［推測：候補 14 × 種類 34 のシャンテン数の計算］。速くするのは次回（受け入れの差分計算など）
