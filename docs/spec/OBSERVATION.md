# OBSERVATION — RL の観測に入れる情報（案）

状態：2026-11-28 の案（仕様だけ。実装は次回、`crates/mj-features`）。`docs/02_RL_DESIGN.md`（ネットワークの入力・価値関数・補助タスク）と `docs/spec/REWARD_CONFIG.md` §5（報酬設定をモデルの入力に渡す形）に沿う。

## 1. 方針
- **方策（actor）には、その席が見てよい情報だけ**を入れる（席視点版の牌譜 `seat:N` と同じ範囲。LOG_FORMAT §5）。作り方も「席視点版の牌譜をなぞって作る」にして、隠れた情報が混ざらないことをテストで確かめる
- **価値関数（critic）には隠れた情報も入れてよい**（全員の手牌・牌山の残り。学習時だけ。02_RL_DESIGN「価値関数」）。方策の入力とは別の区画にし、方策からは見えないようにする
- **最初から③（半荘）の形にする**：1局戦でも点数状況・局数・本場・供託・人数・ルール設定・報酬設定を入れる（定数になるだけ。02_RL_DESIGN「ネットワークの入力」）
- 三麻・四麻で同じ形（席の枠は4つ。三麻は4つ目を空にする。行動の番号表と同じ考え。D-007）
- 観測は判断ポイントごとに作る（D-022。選択肢が1つの場面では作らない。D-027）。合法手マスク（325、`mj_features::legal_mask`）を一緒に返す
- 時系列（打牌の順・手出しとツモ切り・立直の宣言牌）は位置の情報を付けて持つ（Q-006「位置エンコーディングを最初から入れる」）

## 2. 方策の入力（公開情報＋自分の手牌）
### 2.1 自分の手牌
| 項目 | 形の案 |
|---|---|
| 手の中の牌 | 34 種 × 枚数（0〜4）、赤は別に 3（5m・5p・5s の赤を持っているか） |
| ツモった牌 | 37（ACTION_SPACE §2 の牌の番号）の one-hot、ツモ後でなければ 0 |
| 自分の副露・暗槓・北抜き | §2.2 と同じ形（自分の席の分） |
| 自分の状態 | 立直中か・一発の権利・フリテン（打牌・同巡・立直後）・聴牌か（シャンテン数は補助の特徴として入れるかを決める。§4） |

### 2.2 全員の公開情報（席は自分から見た相対の位置：自分・下家・対面・上家）
| 項目 | 形の案 |
|---|---|
| 河 | 打牌の列（牌の番号・手出しかツモ切りか・立直の宣言牌か・鳴かれたか・何巡目か）。長さの上限を決めて詰める |
| 副露 | 種類（チー・ポン・大明槓・加槓・暗槓）・牌・誰から鳴いたか・いつ（何巡目か） |
| 北抜き | 枚数（三麻のみ。抜いた順番も時系列に入れる） |
| 立直 | 立直したか・宣言した巡目・ダブル立直か |
| 点数 | 持ち点（1万点単位などで正規化）、自分との差 |
| 局の状態 | 場風・局数（何局目）・親の位置・本場・供託・ドラ表示牌（めくられた分）・ツモ山の残り枚数・巡目 |
| 対局の状態 | 規定の最後の局か・延長戦中か・終了点数との差（D-012 の1局戦では定数） |
| 見えている枚数 | 34 種 × 見えている枚数（自分の手牌・全員の河・副露・北抜き・ドラ表示牌）。`mj-bots` の `PublicView` と同じ数え方 |

### 2.3 ルール設定（D-007：ルールの入力特徴を最初から持たせる）
- `Rules` の項目のうち、打ち方に効くものを数値・one-hot で入れる（人数、萬子、赤の枚数、チー、北抜き、ツモ損、終了点数、返し点・ウマ、本場・聴牌料の額、形式聴牌、包、ダブル役満、喰いタン・後付け など）
- 入れる項目の一覧と変換は `catalog.rs` の項目（キー）から作り、カタログを足したら一覧も足す（テストでカタログとの対応を確かめる）
- 学習中はルールを切り替えない（D-007）ので、ここは定数になる。別ルールへの追加学習のときに効く

### 2.4 報酬設定（REWARD_CONFIG §5、D-021）
| 特徴 | 値 |
|---|---|
| 順位点（正規化） | `rank_points[i] / scale`（4人分の枠、三麻は4つ目を 0） |
| 持ち点の係数（正規化） | `score_coef × 10000 / scale` |
| 基準点との差 | `(今の持ち点 − score_base) / 10000`（係数 0 なら 0） |

- 入れるのは自分の席の設定だけ（他家の報酬設定は実際の対局では分からない）

## 3. 価値関数だけの入力（隠れた情報、学習時だけ）
- 他家の手牌（34 種 × 枚数、赤）、他家のシャンテン数・待ち（補助タスクのラベルと同じもの）
- ツモ山の残りの中身（種類ごとの枚数）、裏ドラ表示牌
- 他家の報酬設定（抽選した席ごとのプリセット）

## 4. オーナーに決めてほしいこと
1. **自分のシャンテン数・受け入れを入力に入れるか**：入れると学習が速くなる見込み［推測］だが、エンジンで計算した「答え」を渡すことになる。入れない場合は補助タスク（02_RL_DESIGN）のラベルだけにする
2. **河の長さの上限と時系列の持ち方**：1局の打牌はボット同士で1人あたり平均 15〜20 枚程度［推測：三麻1局戦の手数からの見立て、未実測］。固定長の配列（例：1人 24 枚）にするか、イベント列としてトランスフォーマーに渡すか（Q-006 のモデル構造と一緒に決める）
3. **ルール設定の入れ方**：全項目を入れるか、打ち方に効く項目だけにするか（全項目なら 98 項目、多くは真偽値）
4. **点数の正規化の幅**（1万点で割る、など）と、三麻・四麻の点数の大きさの違いをそろえるか
5. **ドラの扱い**：ドラ表示牌だけを入れるか、ドラになる牌（表示牌の次の牌）に変換して入れるか（三麻の 1m→9m など、ルールで変わる）
