# ACTION SPACE — RL の行動の番号表

状態：D-038・D-039 を反映（2026-11-28）。実装は `crates/mj-features`（`ActionId`）。

## 1. 方針
- **全ルールの和集合**（D-007）で1つの番号表を作る。三麻・四麻、チーあり・なし、北抜きあり・なしなど、どのルールでも**同じ番号表**を使う。使えない行動はそのルールでは合法手に出ないだけ（合法手マスクで 0 になる）
- 番号表は、判断ポイントの選択肢の表記（`docs/spec/DECISION_POINTS.md` §5）と **1対1**に対応する。1つの選択肢は必ず1つの番号になり、1つの番号は1つの選択肢の表記になる
- **番号は一度付けたら変えない背番号**（D-038）。既存の番号は動かさず、行動を足すときは末尾（325 以降）に足す
- 選択肢の並び順はエンジンの並び（DECISION_POINTS §5）を正とし、番号の昇順と一致することは求めない（初版の番号は §5 の並びで振ったので今は一致するが、足した行動で崩れてもよい）
- 方策の出力は 325 個の1段にし、合法手マスクで使えない行動を消す（D-039）
- **変換は mj-core の外**（予定：`crates/mj-features`）に置く。mj-core が返すのは選択肢（`Action`）と、その表記（`Display`／`FromStr`）だけで、番号は知らない（コアに入れるのは状態・合法手・遷移だけ。CLAUDE.md 原則5）
- 選択肢が1つの場面は RL に見せない（D-027）。番号表にはあるが、判断ポイントにならない

### 3.1 ポン（40）
手から出す2枚の組。種類の順に、5の種類（5m・5p・5s）だけは赤の組み合わせで3つに分ける（赤が先）：
- 5 以外の 31 種：`pon:X,X` の1つずつ（31）
- 5m・5p・5s：`pon:5Xr,5Xr`、`pon:5Xr,5X`、`pon:5X,5X` の3つずつ（9）

`pon:5Xr,5Xr` は赤を2枚以上使うルール（`tiles.red_fives` が2以上）でだけ合法手に出る。

### 3.2 チー（57）
手から出す2枚の組（鳴いた牌は打牌で決まるので番号に入れない）。色ごとに次の 19 通り、萬子 → 筒子 → 索子の順（萬子の 116〜134、筒子の 135〜153、索子の 154〜172）：

`1,2` `1,3` `2,3` `2,4` `3,4` `3,5r` `3,5` `4,5r` `4,5` `4,6` `5r,6` `5,6` `5r,7` `5,7` `6,7` `6,8` `7,8` `7,9` `8,9`

（1枚目の牌の番号の順、同じなら2枚目の牌の番号の順。連続する2枚が 8 組、1つ飛びの2枚が 7 組、5 を含む 4 組の赤の組み合わせ）

## 5. 対応の検査（実装時に作るテスト）
1. 番号 → 表記 → 番号が恒等（325 通り）。表記 → `mj-core` の `Action`（`FromStr`）→ 表記が恒等
2. 自己対戦（三麻・四麻、各ルール）のすべての判断ポイントで、選択肢を番号にすると**重複がない**（番号の昇順とエンジンの並びの一致は求めない。D-038）
3. 合法手マスク（325 次元）の 1 の数が選択肢の数と一致する
4. 番号表を変えたら（行動を足すなど）、この文書と `mj-features` の表を同時に変え、既存の番号は動かさない（足す行動は末尾の番号にする。学習済みのモデルの出力層との対応を保つため。D-038）。`mj-features` のテストで、初版の 325 個の番号と表記の対応を固定する

## 6. 決まったこと（2026-11-28）
- 行動を足すときは末尾に足し、選択肢の並びはエンジンの並びを正とする（D-038）
- 方策の出力は 325 個の1段（種類と牌の2段にはしない）。合法手マスクで使えない行動の logit を −∞ にする（D-039、`docs/02_RL_DESIGN.md`「行動空間と合法手マスク」）
