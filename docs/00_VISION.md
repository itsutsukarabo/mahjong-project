# 00 VISION — 目的と全体の進め方

## 目的

自己対戦の強化学習で育てた麻雀AIを中核に、次の3つを1つの土台（BE+FE）で実現する。

1. **AI対局の再生**：学習中・学習後のAI同士の対局を再生して見せる
2. **学習の配信**：自宅のリソースで学習を回し続け、その様子を配信する
3. **ゲームとしてのリリース**：最初は友人と遊べる小規模運営、反響があればSteam・スマホアプリへ

最終的なリリース形態から逆算して、最初から「ゲーム画面に拡張できる再生画面」として作る。

## 長期の目標

自分の打牌判断を自然言語で説明できるAI。
手牌推定・待ち推定などの補助タスクは、この「説明」の材料として育てる。

## フェーズ

### Phase 0：土台づくり
- 三麻ルールセットの仕様確定
- 牌譜（イベント列）形式の確定
- Rustルールエンジンの骨格（既存実装のフォークか自作かを調査して決定）
- majiang-core との差分テストの仕組み

### Phase 1：再生画面とRL環境
- 2D の牌譜再生画面（全員の手牌が見える開発者向け表示を含む）
- RL 環境（Python から Rust エンジンを呼ぶ）
- 報酬カリキュラム①の学習開始

### Phase 2：配信と学習の継続
- 配信画面（最新の自己対戦の再生＋学習統計の推移）
- カリキュラム②③へ進む
- 学習の待ち時間でフロントを段階的に3D化

### Phase 3：小規模ゲーム運営
- サーバー権威型の対戦サーバー
- 友人と遊べる対戦モード（人間とAIの混在可）
- 多機能なルール設定を売りにする
- SNSでの告知と、友人と遊ぶ様子の配信

### Phase 4：本格リリース（反響があれば）
- 求められているニーズを反映
- Steam 版（Electron 等で包む）
- スマホアプリ版（Capacitor 等で包む）

## 進め方の原則

- 再生画面は RL のデバッグ道具を兼ねる。学習を回し始める前に、最低限の再生画面を用意する
- 3D化は学習の待ち時間を使って少しずつ進める。学習を回し始める時点では2Dで十分
- 学習実験は1回が長いので、優先順位づけと「何を確かめる実験か」の明記を徹底する
