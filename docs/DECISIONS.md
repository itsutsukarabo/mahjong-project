# DECISIONS — 決定事項の記録

新しい決定は末尾に追記する。覆す場合は、元の項目を消さずに「変更」として追記する。

## D-001 Unity を使わない
- 過去に Claude と一緒でも Unity をうまく動かせなかった
- シーン・プレハブ・Inspector などエディタ GUI 側に状態が多く、Claude Code から見えない部分が多いのが原因
- テキストのコードだけで完結する構成を選ぶ

## D-002 FE は Web 技術（TypeScript）
- Claude Code が全体を読み書きでき、情報量も多い
- 同じ成果物を Web・Steam（Electron 等）・スマホ（Capacitor 等）に展開できる

## D-003 最初から RL で育てる。天鳳データは使わない
- 天鳳には「競合製品への応用は禁止」の条項があり、天鳳の牌譜で学習したモデルを商用ゲームに載せるのはリスクが高い
- 自己対戦なら補助タスクのラベルも無料で無限に得られる

## D-004 ルールエンジンは Rust で1つに統一する
- 学習の高速化とゲーム BE の高速化を両立できる
- 学習環境と表示用エンジンでルールの実装がズレる問題（train/serve skew）が構造的に起きなくなる
- WASM でブラウザ・Electron・スマホにも同じ実装を持ち込める
- kobalab/majiang-core は「参考実装」かつ「差分テストの基準」として使う

## D-005 三麻から始める
- 報酬カリキュラム①は4人麻雀にも流用できる形にする
- ②は順位点の傾斜を変えて4人麻雀にも流用できる形にする

## D-006 報酬カリキュラム
- ①-a 和了＝+1 → ①-b 局収支（放銃も対称、打点は圧縮）→ ② 局収支＋順位点（+30000/0/−30000、正規化）→ ③ 半荘（局ごとの報酬を予測モデルで作る）
- シャンテン報酬はポテンシャル型
- 詳細は `docs/02_RL_DESIGN.md`

## D-007 学習中にルールをランダムに切り替えない
- 1つのルールに特化させたい。モデル規模（数百万パラメータ程度）を考えても、能力を分散させない方が強くなる可能性が高い
- 別ルールはメインのモデルから追加学習で専用モデルを作る
- 保険として、ルール設定の入力特徴と全ルールを包む行動空間は最初から持たせる

## D-008 FE は 2D から始め、学習の待ち時間で段階的に 3D 化する
- 2D 版は開発者向け表示として残す

## D-009 サーバー権威型
- 牌山と他家の手牌をクライアントへ送らない
- 後で Steam 版に拡張するときに作り直しにならないよう、小規模運営の段階から徹底する

## D-020 報酬の形

## D-042 観測（OBSERVATION §4）の決定
- 自分のシャンテン数・受け入れを方策の入力に入れる。打牌の候補ごとに「切った後のシャンテン数と受け入れ枚数」も入れる（自分の手牌と見えている牌だけから計算する）
- 河・副露・北抜き・立直・ドラ表示などの時系列はイベント列として持ち、トランスフォーマーに渡す前提にする。イベントの順番（位置）を必ず持たせる。列の長さの上限はボット同士の対局で実測して決める
- ルール設定は「打ち方に効く項目」だけを入れる。カタログの全項目に「打ち方に効くか」の印を付け、印のない項目があれば CI を失敗させる
- 持ち点は1万点で割る。他家との点差と今の順位も入れる。三麻と四麻の点数の大きさはそろえない
- ドラは「ドラになる牌」に変換し、牌の種類ごとのドラの枚数として入れる（抜いた北のドラを含む）。表示牌そのものはイベント列に残す

## D-043 観測を作る実装は mj-features の1つだけ

## D-052 対戦相手（RL_TRAINING §3.1 を置き換える）
- ①-a：自分自身とだけ打つ
- ①-b 以降：最新のモデル 50%・過去のチェックポイント 50%。過去は「最新から n バージョン以内」から、新しいものほど重く引く。n と保存の間隔は設定で変えられるようにする。過去のチェックポイントが n 個たまるまでは、足りない分を最新のモデルで埋める
- RuleBot は学習の相手に入れない。評価で「学習が壊れていないか」を見る最低ラインとしてだけ使う
- 学習のデータは最新のモデルの席だけを使う。1つの卓に最新のモデルが複数座っていれば、その全員の席を使う

## D-053 記念のチェックポイント
- 各段の最良のモデルと、一定の間隔で選んだモデルを「記念」として残す。学習の相手には入れず、評価のときだけ対戦させて、過去にできていたことを忘れていないかを確かめる

## D-054 強さの物差し（レーティング）
- チェックポイント同士をデュプリケート方式で対戦させ、強さを数値で表す。RuleBot と記念のチェックポイントも同じ物差しに載せる
- 配信画面で「AIの強さの推移」として見せられる形で記録する

## D-055 カリキュラムの切り替えの目安（RL_TRAINING §2.3 を置き換える）
- ①-a → ①-b：和了率が RuleBot を上回り（最低ライン）、そのうえで直近3回の評価で伸びが止まった
- ①-b → ②：和了率と平均打点がともに安定し、評価での局収支が直近の最良のモデルから伸びなくなった
- ② → ③：評価での報酬（局収支＋順位点）が直近の最良のモデルから有意に伸びなくなった。RuleBot に勝つことは必要条件（十分条件ではない）
- 共通：放銃率・副露率・立直率が極端な値（0% など）になっていないこと（報酬の抜け道の兆候）
- 「伸びが止まった」「有意に」の判定方法（評価の局数・信頼区間）は RL_TRAINING §6 に具体案を書く
