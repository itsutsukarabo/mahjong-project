# 03 FRONTEND — フロントエンドの進め方

## 技術

- TypeScript + Vite
- ルール処理は Rust エンジンの WASM を使う（FE でルールを再実装しない）
- 2D 描画：DOM（D-059。牌譜再生画面は開発者向けで、画面のスナップショットを安定させやすい）
- 3D 描画：Three.js
- 描画の回帰テスト：Playwright で画面のスナップショットを撮って比較

## 構造

```
牌譜（イベント列）
   │  WASM エンジンに順に流す
   ▼
卓の状態（view model）
   │
   ├─ 2D レンダラー（開発者向け：全員の手牌を表示）
   └─ 3D レンダラー（見せる用）
```

- **FE の状態＝イベント列を WASM エンジンに流して得た卓の状態**
- 「卓の状態 → 画面」の描画層を分離し、レンダラーを差し替え可能にする

## 進める順番

1. **牌譜再生画面（2D）**
   - RL のデバッグ道具を兼ねる。学習中の AI が何をしているかを目で確認するため最優先
   - 全員の手牌を表示する開発者モードを持つ
   - 巡目のシーク、早送り、巻き戻し
   - 配置（PC の横画面・スマホの縦画面、三麻の空いた席）、手牌の下の帯（打牌の区画。牌譜再生では AI の判断の表示に使う）、アニメーション、結果の窓の仕様は `docs/spec/REPLAY_UI.md`
   - アニメーションは「前の卓の状態と次の卓の状態の差」から作る（画面側でルールの判断をしない）
2. **配信画面**
   - 学習プロセスから最新の自己対戦を WebSocket で受け取り再生する
   - 学習統計（和了率・放銃率・平均順位など）の推移を重ねて表示する
   - OBS のブラウザソースで取り込めること
3. **3D 化（学習の待ち時間で段階的に）**
   - 2D 版は捨てずに開発者向け表示として残す
   - 牌は最初はコードで作る（角を丸めた直方体＋牌面テクスチャ）。モデリングによる作り込みは後回し
4. **ゲームモード**
   - 合法手の判定はエンジンから受け取り、FE は入力を受けて表示するだけ
   - 再生画面に操作を足す形で作る
   - 打牌は手牌の下の帯の区画を押して選べるようにする（区画と行動の表記の対応は `@mj/table-model` の `bandSlots`。REPLAY_UI §4.2）

## 品質（高画質・高フレームレート）

- 136枚（三麻は108枚）の牌はインスタンシングで描画命令をまとめる
- オブジェクトを毎フレーム作り直さない
- テクスチャアトラスで描画命令を減らす
- 高 DPI 対応（devicePixelRatio）、アンチエイリアス
- AI 推論は Worker で行い、メインスレッドを止めない
